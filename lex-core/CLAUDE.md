# CLAUDE.md — lex-core

## Purpose

Entropy-based Wordle solver. Pure computation — no I/O. Depends only on `lex-data` for the `Word`/`WordSet` types.

## Module map

`build.rs` hashes every file under `src/` plus `Cargo.toml` (sorted by path, path and contents) into `SOLVER_DIGEST`, which names the solver source in each Track snapshot's header. Any edit to `lex-core`, a comment included, changes it.

All public types are re-exported from `lib.rs`: `use lex_core::{Guesser, Guess, Strategy, GuessPool, Suggestion, WordCorrectness, Correctness, GameResult, play}`.

## Decision tree (`tree.rs`)

A game position is identified by its guess path: the `(guess word, feedback ordinal)` steps from the
root. For a fixed starting (pool, Answer list) the path determines the candidate set, and `Candidates::suggest_index`
is deterministic, so a node computes its suggestion once and every later game reaching it reuses
it. Edges are sparse (`HashMap<(Word<N>, u64), NodeId>`: 3^N possible patterns) and
keyed by the guess word as well as the pattern, because callers may push guesses that were not the
suggestion (`assist` does). Ordinals are `u64` at every length; a const assertion in `correctness.rs` checks that
3^`MAX_WORD_LENGTH` fits. If `suggest` ever gains randomness or hidden state, the cache is invalid. The `Strategy` is fixed per tree (a `Guesser` takes it at construction), so the tree's identity is (pool, Answer list, `Strategy`).

`Guesser` owns the tree behind a `RefCell` (the memoizing queries take `&self`), so it is not `Sync`; `Guesser::reset()` starts a
new game on the same tree, and `play` takes `&mut Guesser` for that reason.

## Opening book (`book.rs`, `tree.rs`)

`Guesser::build_book()` books, top-down, every position whose work (guesses its `Allowed` permits x candidate count) exceeds `BOOK_FLOOR` (40 M pattern evaluations, `benchmarks/experiments/book-floor.md`); `build_book_with_floor` takes the floor so tests can lower it. Work never rises along a path, so the booked positions are a subtree. Each booked node stores the guess `DecisionTree::suggest` chose and, from the same decision, the technique and the top 10 guesses with their scores (pool index, expected bits, Expected remaining, entropy score, Guess cost where computed, as `f64`): `build_book` switches recording on for the build and reads the `Record` each booked position already made, so nothing is searched twice (a position decided earlier without recording is decided again from the warm memos). Candidacy, permission and the pattern distribution are recomputed at lookup. Scores stay in memory only while the book is loaded with `keep_scores`; a book without them seeds the same play path and explains nothing at booked positions; a child is booked only if its own work exceeds the floor. `Guesser::with_book` seeds a tree: a node created by playing the booked guess with a booked edge takes the booked child's guess as its pre-filled suggestion and stays on the book; any other guess leaves it. The book holds no Candidate sets, so nodes still filter on creation. The test-only `booked_computations` counter proves a seeded run never searches at a booked node. A book is valid only for the pool, Answer list and Strategy it was built for; `lex-data` stores it under a key of the Corpus and Profile checksums, the length, `Strategy::key_fields()` (every field as an ordered `(name, value)` pair; a destructuring without `..` makes a new field a compile error there) and `SOLVER_DIGEST`. `Guesser::build_book_reporting` reports each booked position for progress. `tests/book_heap.rs` owns a `dhat` global allocator and holds the book's heap against the 1 GB cap (the English-5 case is `--ignored`).

## Endgame search (`endgame/`)

On by default (`Strategy::DEFAULT.endgame_threshold` is 10); off when it is 0. `BasePolicy::guess_index` calls `Endgame::best_index` for
sets with 2 to threshold candidates and otherwise falls back to `Candidates::suggest_index`; the tree's
`BasePolicy` owns the `Endgame`, so its memo is shared by every game. Costs are weighted sums using pool-wide prior weights,
so a set's cost is independent of the position it was reached from. The memo is keyed by the sorted
candidate indices and the allowed guesses (a cost under fewer allowed guesses must not be reused for more); an
`Allowed::List` keys an inner map by the list itself (`Memo`), and in normal mode and on an ultrahard Corpus run the allowed set is implied, so the key is the candidates alone. Plain objective: sum of weight x guesses to finish. With
`endgame_aversion = L > 0`: sum of weight x a^guesses, a = e^L; the exponential is what keeps the cost
independent of depth (a penalty past guess 6 would not be).

`search` computes a lower bound per guess from its partition (a group needs one guess for the answer it
names and two for each other), sorts by it, and stops once the bound exceeds the best cost. A
non-candidate that leaves the set in one group is skipped, which guarantees the recursion shrinks it.
Ties go to a candidate, then pool order. The try order is drawn from a `BinaryHeap` keyed `(floor, outside, index)`, a unique total order, so the few guesses tried before the break cost a pop each rather than a sort of the pool; the test-only `scan_all` sorts it whole. In plain mode, sets of 2 and 3 take closed forms that repeat `try_guess`'s sums operation for operation (a pair's optimum is always a candidate, so no memo lookup), and the pool is not scanned when the best candidate is below `2 * mass` by a relative `SLACK` of 1e-9: an outside guess leaves every answer a guess to go, and the slack means no float rounding can change the winner (nearer ties are scanned). Candidate-first scanning for larger sets was tried and rejected: its weaker early best recursed into more child sets than the global floor order. Candidates are always allowed guesses: `Whole` holds the pool, `Candidates` is the set, a `List` contains them. The test-only `reference` flag restores the full sort, and `the_fast_paths_match_the_full_search_bit_for_bit` holds the fast paths to it with `to_bits`. The first `scan` of a top-level `solve` (the only entry; the recursion is `solve_within`) builds a `PatternTable` once for the call, so a closed form that returns never pays for one; it lives in a `thread_local!` buffer reused between calls, borrowed once per top-level `solve` or `cost_of` and handed down the recursion as `&mut PatternTable`, never across a rayon call (a solve runs none), so every `Endgame` entry point takes `&self`: a row per guess the call allows (the pool for `Whole`, the list, or the set for `Candidates`) and a `u8` column per answer of the set, holding the rank of that answer's pattern among the row's distinct patterns in ascending ordinal order, with the row's ordinals alongside. A row's pairs come from the block kernel and are ranked by one sort and a sweep. `floors`, `try_guess` and `triple` map their set to table columns once per call (identity at the top level, a binary search per answer otherwise), then read the table. `floors` reads ranks directly: per row it accumulates (mass, heaviest weight) per rank walking the set in index order, then adds the groups in ascending rank, skipping the win rank and empty ranks, so no sorted partition is built and the sums are the bits `floor` gives over `Pool::partition` (`floors_read_from_ranks_equal_floors_over_the_sorted_partition`). `try_guess` and `triple` use `PatternTable::partition`, a counting pass (counts, prefix sums, placement in set order) whose groups equal those of `Pool::partition` in the same order. A guess or answer outside the table trips a debug assertion and falls back to `Pool::partition`. Sets over 255 answers and the test-only `reference` path (`scan_all`) skip the table. A mixed bound inside `try_guess` (solved costs plus floors of unsolved groups) was tried (#119) and rejected: bit-identical but no Speed bar gain, because the child solves it skipped were almost all memo hits (memo-miss searches fell 0.3%). A `std::simd` structure-of-arrays `floor_from_ranks` (vector group floors, ordered sum) was tried and rejected: 15 to 30% slower on the floors benches, since the ordered sum is the cost and sets are small. Children are solved without any bound passed down, so memoized
costs are exact. `win_weight` is ignored here. A top-K entropy probe limit was tried and rejected
(`benchmarks/experiments/endgame.md`). The opt-in test `real_corpus_roots_match_simulated_cost` checks predicted
cost against simulated games on real roots.

## Rollout (`rollout.rs`)

Off unless `Strategy::rollout_k > 0`. `DecisionTree::suggest` dispatches by candidate count `n`: `Rollout::best_guess` for `max(endgame_threshold, 2) < n <= ROLLOUT_CAP`, otherwise the `BasePolicy` (the Endgame for 2 to `endgame_threshold`, else greedy). Rollout takes `Candidates::suggest_top_k(rollout_k)`, plays each guess out under the `BasePolicy` (the tree's own without rollout), and keeps the guess with the lowest expected guesses `1 + sum share * base_cost(child)`, children summed in ascending feedback ordinal with `mul_add`. A strictly lower cost wins with no epsilon, so an exact tie keeps the higher-scored guess; a guess that leaves the set whole costs infinity.

Costs use the same pool-wide prior weights as the Endgame, so a set's `base_cost` is independent of the position it was reached from. The rollout owns the memo, shared by every game and counted in the memory cap, keyed by the sorted candidate indices and the allowed guesses through a `Memo<f64>`; the Endgame has its own. `Endgame`, `Rollout` and `BasePolicy` entry points take `&self` and `Endgame` and `Rollout` are `Send + Sync` (a compile-time test holds this; the test-only `evaluations` counter is an `AtomicU64`). `lex-core` owns no pool: `choose` scores its played-out guesses, and `guess_cost` its child sets, with rayon indexed `par_iter().map().collect()` into one slot each, then folds the slots sequentially in today's order (the winner with a strict `<`, the child costs with `mul_add` in ascending feedback ordinal), so the result is bit-identical at any thread count (`the_choice_and_the_played_out_list_do_not_depend_on_the_thread_count`) and runs in the caller's pool (`--threads`; one thread is serial). Two threads may both miss the memo on one child set and solve it twice, to the same value; there is no in-flight dedupe, since waiting inside the Endgame's recursion risks deadlock. The Endgame never calls rayon, so Rollouts do not nest and its thread-local `PatternTable` is safe. `ROLLOUT_CAP` and `ROLLOUT_MULTIPLIER` are compiled in, not Strategy fields; `DecisionTree::work` scales a rollout position by the multiplier so `BOOK_FLOOR` still counts pattern evaluations. The opt-in test `real_corpus_rollout_reproduces_the_spike_band` replays English-5 with the band forced to 12 to 300 (a test-only floor override) and checks the spike's prior-weighted 4.1569; it also prints the measured multiplier.

## Explanations (`explain.rs`)

`Guesser::set_explain(true)` (off by default) makes each position record what it weighed when it decides; `explain()` returns it and `score(word)` prices any word on demand. The gate is `DecisionTree::recording` plus an `Explainer`: `suggest` runs the original dispatch unless both are set, so a `simulate` run executes the same code as before and the per-node cost is nil (records live in a side `HashMap` on the tree, not on `Node`). Recording reuses what the solver computes: the Rollout's `choose` pushes each `(Scored, cost)` it already has into an optional sink, the entropy list is `top_k(10)` (its first element is `suggest_index`'s by the same total order), and the Endgame's pick and cost come from the same memoized `solve` (`best_with_cost`). Only Expected remaining, the Endgame's non-pick entries and the chosen guess's pattern distribution need a partition each, at decision time. Technique per position follows `suggest`: a lone candidate is Entropy; the Endgame lists the pick (with its Guess cost), then the other candidates in pool order; a Rollout lists the `rollout_k` guesses it played out, sorted by Guess cost. Guess cost is expected guesses counting the guess, or ln(E[a^g]) / ln(a) under `endgame_aversion`. A booked position explains from the stored technique and top guesses (`from_book`) with its distribution recomputed; the Explanation equals the online one bit for bit (`a_booked_explanation_equals_the_online_one_at_every_booked_position`). A book loaded without scores explains `None` at booked positions. `score` asks `Endgame::cost_of` (one try, children through the memo) or `Rollout::cost_of` (warm memo); a word the Guess pool rule forbids is scored and flagged `permitted: false`, and one outside the pool is `None`. `explain` returns `None` when recording is off or the position was decided before it was switched on.

## Allowed guesses (`allowed.rs`)

Each tree node stores an `Allowed` beside its candidates, a function of the guess path built by `Allowed::after(mode, pool, guess, feedback ordinal)` from its parent. `GuessPool::All` keeps `Whole` (every pool word). `Hard` filters the parent's allowed words by `HardRule`, Selby's `okhard`: the guess's greens stay in place, and its green and yellow letters reappear with at least the scored multiplicity (grays may be replayed, a yellow may repeat its position). `Ultrahard` keeps the words that score the guess exactly as played; on a Corpus run (the root candidates are the whole pool) the allowed set is the candidates at every depth, so the node stores `Candidates` and nothing extra. Otherwise a node holds a sorted index list that always contains its candidates. `Guesser::rule_violation(word)` re-derives the same rule from the history for `assist`, with a one-line reason.

## Strategy and scoring (`strategy.rs`, `candidates.rs`)

The guess pool is immutable (every loaded word); a `Candidates` is a sorted index list into it, starting as exactly the Answer list's pool indices (`Guesser::new` borrows the `&WordSet` and the `&[Word]` and always takes one: every pool word on a Corpus run, a Profile's list otherwise; mapped once through a `HashMap`, sorted ascending so frequency order holds; an answer missing from the pool panics). The prior is always taken over the surviving candidates, so a Profile's Answer list restricts it without changing its formula. `filtered` copies indices, not words. `suggest` scores every guess the `Strategy` allows
(see Allowed guesses below) as
`entropy + win_weight * P(guess is the answer)`, with probabilities renormalized over the surviving
candidates each time (`Pool::prior`: softmax of ln-frequency over T, relative to the survivors'
maximum, which keeps ultrahard with `win_weight = 0` bit-identical to the pre-strategy solver).
Strict-greater wins; on an exact tie a candidate beats a non-candidate, then frequency order. A
single candidate is returned without scanning the pool. `answer_prior` exposes the same softmax
for reports; the CLI fixes the report prior at `CANONICAL_TEMPERATURE`. Cost is O(pool x candidates)
per node, the reason memoization matters.

The entropy scan is transposed (`transposed.rs`). `for_each_guess` gathers the Candidate set once into `Columns<N>`: N byte columns (column i holds letter i of every candidate, in set order), padded with never-matching words to whole blocks of `BLOCK` = 64, plus one count plane per Alphabet letter (`counts[letter * blocks + k][b]` is how many times word b of block k holds the letter, so the planes cost `Alphabet x words` bytes). Per guess, `Plan::new` splits the guess's letters into once-only and repeated. A block is scored as two `std::simd` vectors of 32 words (`u8x32`, one AVX2 register; NEON splits it; `portable_simd` is a crate feature): green by a column compare; a once-only letter that is not green is yellow exactly when its count plane is nonzero (every occurrence in the word is unmatched, since the guess has no other); for a repeated letter g the word's unmatched count is g's count plane minus the greens on g, spent left to right over the guess's non-green occurrences of g. The digits fold to an ordinal in `combine`: five digits per byte (3^5 = 243), then the chunks in the narrowest integer that holds the running value (`u16` to 10 digits, `u32` to 20, `u64` above), so the wide multiplies are few. `Ordinal` (`u32` or `u64`) is the width the block is written at: `entropy_columns` picks `u32` for N <= `MAX_U32_LENGTH` (20) and `u64` above, at compile time. The kernel's asm before this (auto-vectorized `u64` lanes) spent most of its instructions widening and multiplying digits and shifting `u64` presence masks out; `cargo asm` (in the dev shell) on the bench binary shows the current loop at a few dozen vector ops for N = 5. No `core::arch` is used. The result is exactly `pattern_ordinal`'s, held by proptests on tiny and wide alphabets for N up to 25 at both widths. `filtered` and `Pool::partition` stay on `pattern_ordinal`; the Endgame's `PatternTable::build` reads the kernel (a `Columns` of the set, one `Plan` per row), and its rows are the table the scalar build produced.

`guess_entropy_columns` writes a block's ordinals to a 64-entry buffer, then adds the masses in word order, so the sums are the scalar counters' bits. It dispatches on a `const` memory rule: dense buckets while 3^N x 8 bytes <= `DENSE_BOUND_BYTES` (16 MiB, N <= 13), else sort-and-run: `(ordinal, p)` pairs stably sorted by ordinal so each run's mass accumulates in word order, runs summed in ascending ordinal through the same `entropy_from_masses` (production reaches it at every length above 13). The scalar `guess_entropy` over `pattern_ordinal` is kept for tests and benches (`entropy_16_guesses_old` / `_new`, `gather_1000`, at N = 3, 5, 9, 15, 25) and a proptest and a scan-level test assert the two agree bit for bit.

Dense counter: accumulates probability mass per feedback ordinal. The working memory is one thread-local `Scratch { buckets, touched, pairs }`, shared by every word length and taken out of the thread-local once per scan (`Scratch::take`, handed back with `give_back`), not once per guess: `buckets` grows to the largest `WordCorrectness::<N>::COUNT` (= 3^N) seen and is all zero between guesses; `touched` lists the ordinals a guess wrote (a bucket is listed when it is 0.0 before the add, so every prior must be positive). `finish_dense` sorts `touched` ascending, sums `p * log2(p)` in that order while zeroing each bucket, and clears the list. The ascending order makes the floating-point result independent of word order, which keeps guess sequences bit-identical.

## Correctness algorithm (`pattern_ordinal` in `correctness.rs`)

Letter count over the Corpus Alphabet at every length (ADR 0010). `Pool::new` maps each word through `WordSet::alphabet()` (sorted letters, index = position) to a `Code<N> = [u8; N]` stored beside the `Word`; a letter outside the Alphabet encodes as `UNKNOWN_LETTER` (255), which no pool word holds, so an `assist` guess with foreign letters scores as absent for them. An Alphabet over 255 letters is a typed `LexDataError::AlphabetTooLarge` at `DataDir::load`; `Pool::new` panics on one built some other way.

`pattern_ordinal(word, guess, counts)`: pass 1 tallies each non-green word letter in `counts` (a `[u8; 256]`); pass 2 walks the guess left to right: green if equal, else misplaced when the letter's tally is positive (spending one), else absent. It then zeroes the entries for the word's letters, so `counts` is all zero between calls and a caller makes one on its stack per scan (`filtered`, each entropy scan, `Pool::partition`). Linear in N. `WordCorrectness::correct` takes `Word`s, so it indexes letters by first appearance in the pair (at most 2N values) and calls the same function. `compare_ordinal` (test and bench only) is the old O(N^2) compare, kept as an oracle and as the "old" side of the `ordinal_count` / `ordinal_compare` benches (`consts = [5, 10, 13, 25]`).

The earlier rejection of alphabet-indexed `[u8; N]` words (`benchmarks/experiments/micro-opt.md`) was a length-5 speed result; the single-technique decision in ADR 0010 supersedes it, gated on English-5 CPU time in the PR that introduced this.

## `ordinal()` encoding

`WordCorrectness` is encoded as a base-3 number (position 0 = most significant digit). `Absent = 0, Misplaced = 1, Correct = 2`. All-absent = 0; all-correct = 3^N − 1. This gives a compact index into the pattern probability array.

## Micro-benchmarks

divan benches live in a `#[cfg(feature = "bench")] mod benches` beside the code they time, so they reach crate-private items; `benches/lex-core.rs` is only the `divan::main()` entry. Run `cargo bench -p lex-core --features bench`; a trailing argument filters by bench path (`-- ordinal_count`, `-- --exact correctness::benches::correct_no_overlap`).
